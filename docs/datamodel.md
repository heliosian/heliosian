# The data model

`internal/db` declares the data model's tables, one sheet tab each, in `db.Tables`: every table's name, the spreadsheet it lives in, the columns that key a row, and each column's kind. A tab and its columns are named exactly as the table and its columns are (`PERSON`, `vc_name`), so the sheet, the code and a query share one name for everything. `tools/createtabs` lays out the five spreadsheets from it - `Data: People`, `Data: Groups`, `Data: Documents`, `Data: Mail` and `Data: Config`, each with its Change Log - and their ids are the `DATA_*_SHEET` variables (`docs/deploy.md`, Configuration values). A generated table (`EFFECTIVE_MEMBER`, `INBOX`) and a generated column (`PERSON.name_show`) are declared beside the stored ones and have no tab or column in a sheet: `Table.Stored` is what a tab holds.

## The store

`db.NewStore` is a `store.Store[db.Model]` over the five sheets (`docs/storage.md`, Store), one part per spreadsheet, each tab's columns its table's stored columns and its key the table's. The server builds it in `app.NewCore` on the same queue as the apps' store, so both load at startup, refresh together and commit in one order; `tools/loadcheck` loads it too and prints each table's row count, and the sample server reads `sampledata/data*/`.

A part's build checks every row (Cells, below), computes the generated columns into a copy of the row (`Table.Generate`: a person's `name_long`, `name_short` and `name_sort` are the override if set, else the import's, and `name_show` is `name_long`, else `Guest` for a guest, else `[Missing Name]`), refuses two rows with the same key, and indexes each table by its key (`Rows.Get`) and by every reference column (`Rows.Referencing`). People's build also refuses a person with addresses but not exactly one `primary`. Mail's part reads the other four, so a change to any sheet rebuilds it, and its build refuses any reference, in any table, that names no row (`Model.Has`). A commit the model refuses is refused whole, as for every part.

## Queries

A query is one fully bracketed prefix expression, the operator first in every bracket: `(from TABLE [@name] (where cond…) (order path asc|desc …) (limit N) (include path…))`. A condition is `and`, `or`, `not`, a comparison (`=`, `!=`, `<`, `<=`, `>`, `>=`), `(in x "a" "b")` or `(in x (select TABLE.column cond…))`, `(blank path)`, `(exists TABLE [@name] cond…)`, or a yes/no path on its own; a value is a path, a quoted string, a number, `true`, `false`, `today`, `now`, `(count TABLE [@name] cond…)` or `(sum path TABLE [@name] cond…)`. Upper-case names are tables. A path is columns joined by dots, each but the last a reference followed to the row it names; it starts at the innermost row being matched, or at a named one (`@g.visible_to`), or at `@viewer`, the person the query runs as. Several conditions in one bracket are anded.

`db.Parse` reads a query and checks it against the schema before anything runs: a column or table that does not exist is refused with the nearest name (`no column grde on PERSON; did you mean grade?`), and each literal is read as the type of what it is compared with, so an enum value it does not have, an ID of the wrong table, text where a number belongs or a malformed date is refused. `Query.String` renders the canonical form: a bracket that fits in 80 columns stays on one line, otherwise its arguments go one per line, aligned under the first, a `from`'s parts each on its own line indented two, and the rendering parses back to the same tree.

`Model.Run(query, db.Env{Viewer, Now})` answers the matching rows in order, at most the limit, and every row the includes reach, by table and key. Comparisons follow the column's kind: text and enums ignore case, references and IDs match exactly, numbers and amounts compare as exact decimals, a date against a moment as that day's midnight, and an order key by `store.CompareKeys`. A blank cell equals nothing and orders after everything, `!=` holds when exactly one side is blank, and `=` on a list of references holds when the list contains the value. An equality between a reference column of the row being scanned and something outside it is answered from the model's indexes rather than by scanning.

## Effective members

`EFFECTIVE_MEMBER` is generated: who is in a group, with each person's `status` from their member row and the `reasons` they are in (`member`, or `rule` and the rule's order). It starts from the group's `member` rows whose status is set and is neither `excluded` nor `cancelled`, adds everyone an include rule selects, then takes away everyone an exclude rule selects, everyone with an `excluded` member row and everyone deactivated, however they came in. A rule selects with every selector it fills in at once: a target group's own effective members (with its descendants through `parent` when `descend` is set), one person, free text found in a name or an address, or a person column (`property`, which the load refuses if `PERSON` has no such column) holding `value`; then expands them to their `parents` (the leads of families they are in but do not lead), `children` (the members who are not leads of families they lead) or `household` (everyone in their families, and themselves), and keeps only those in `within`'s effective members. A group already being resolved further up the same chain contributes nobody, so lists that include each other resolve. Each group's members are worked out the first time a query asks, once per version of the model. `INBOX` is not built.

## IDs

An ID is a three-letter prefix naming what it identifies, then 11 symbols of upper and lower case letters and digits, about 65 bits; the prefixes are the `*Prefix` constants in `internal/db/id.go`. IDs are case-sensitive and are never trimmed: `db.ParseID` accepts only the exact form and answers the prefix, and `db.TableOf` the table keyed by that prefix, so an ID found anywhere - a URL, a log line, a cell - says which table holds it. `db.Mint` draws a new one, again while `taken` refuses it. A `purchase_id` is minted the same way but keys no table.

## Cells

`Column.Check` and `Table.Check` read a cell as its kind requires: an enum one of its values in any case, a reference an ID whose prefix is its target table's (any table's for `MESSAGE.about` and `ALIAS.id`), a list of references comma-separated, a yes/no, a date or moment, an order key, an address or a link as `internal/cells` and `internal/store` read them everywhere else, and an amount as digits with up to two decimal places. A blank cell is accepted unless the column is required; a column a sheet holds that the table does not declare is ignored.
