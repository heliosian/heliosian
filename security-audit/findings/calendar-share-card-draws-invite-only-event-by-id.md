Description: Helios When's public share card and banner, `/open/share/{id}.png` and `/open/banner/{id}`, and the preview tags on the signed-out page for `/e/{id}`, give any event's title, date, place, picture and the start of its description to anyone holding its id with no sign-in, so an invite-only event's words are readable by whoever a link is forwarded to.
Status: wontfix
Severity: low
---
`shareCard` (`internal/calendar/share.go`) and `banner` (`internal/calendar/invites.go`) resolve the id with `event` (`share.go`), which falls through to `Model().Event(id)` for anything not on the public calendar, and both sit under `/open/`, where the token in the address is meant to be the whole check (`docs/dev.md`). `PreviewHead` (`share.go`), wired into the sign-in page a signed-out fetch of `/e/{id}` gets, finds the event the same way, and `eventHead` puts the day, the hours, the place and `blurb(e)` - the description's first 200 or so characters - into `og:description` and `twitter:description`. For an event shared as Invite Only, anyone with the id gets the title, the day, the hours, the place, the flyer or picture and the start of the description - not the guest list.

`curl https://when.heliosian.com/open/share/<id>.png` and `curl https://when.heliosian.com/e/<id>` signed out.

Left as it is: the preview is the product. A link to an event previews in a chat app, and the preview fetcher carries no session, so whatever the preview shows has to be served to anyone holding the address; closing any of these routes, or thinning what they carry, breaks the preview the event's link was made to give. An outside invitee's `/ext/{token}` previews through the same card and tags by the event's id. The id is the key: a generated one is eight characters from a 32-letter alphabet (`newEventID`, `internal/calendar/handlers.go`), about 40 bits, not guessed in practice, so the reader is someone a link holder chose to send it to, and what they get is the teaser the sender meant the preview to show; opening the page itself still takes sign-in and, for an invite-only event, a place on its list. A human-chosen id is as guessable as its host made it. Pending and declined events are link events (`sees`, `internal/calendar/rsvp.go`), so the card drawing them by id matches what their page allows.
