Description: `Mailgun.Stored` sends the account-wide Mailgun API key as basic auth to whatever URL it is handed - a hook's `message-url` field, or the `Source` cell of a Loop `Messages` row read at startup - so someone who can hand-edit the Groups sheet, or replay one signed notification, is sent the key.
Status: fixed
Severity: medium
---
`Mailgun.Stored` built a GET to the URL it was handed and `do` added the account key as basic auth, with the URL never checked. It came from the `message-url` field of the three hooks, which Mailgun's signature does not cover - it signs the timestamp and token only - and, at startup, from the `Source` cell of any Loop `Messages` row still `received` or `stored`. A content manager of the shared drive adding a `Messages` row with a `Source` of their own, or anyone replaying one signed notification with the URL swapped, was sent the key, which sends as every domain and reads every stored message.

Fixed by taking the message in the notification itself rather than fetching it back: the routes are `forward()` to an address ending in `mime`, so Mailgun posts the raw message as `body-mime`, and `Stored` is gone with the `Store` field of each app's mail and the `Source` column. The key now leaves the server only to `api.mailgun.net`, to send. Loop's hook archives the message and writes its `Messages` row before it answers, answering 500 so Mailgun retries when either fails, and the worker and a restart read the archived copy (`internal/loop/mail.go`; `docs/loop/data.md`, Mail). The calendar's hook reads the reply out of the call (`internal/calendar/replies.go`), and Ask's files the message before it answers, 500 on a failure (`internal/artifacts/inbox.go`). The Mailgun routes have to be changed to match: `docs/deploy.md`, the Mailgun key.
